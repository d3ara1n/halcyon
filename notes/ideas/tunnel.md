# 隧道

隧道是 IPC 的**数据面**：一种基于单页共享内存的进程间批量数据交换机制。三面分工中大块流式数据归隧道：小数据走消息（[message](message.md)），事件通知走信号（[signal](signal.md)）。

机制本身**方向中立**：一条隧道就是一页共享内存加两个端点，不含任何方向概念。单工/双工是协议层的事——双工即两条反向的单工隧道组合。

## 内核职责：四件事

内核不理解也不解析页内数据（协议无关），只提供：

| 操作 | 语义 |
|------|------|
| `TunnelCreate` | 分配一页物理帧（零态）、建立登记项 `{随机 id, 两端}`，按调用方指定的地址映射进己方空间，返回隧道 id |
| `TunnelAttach(id, addr)` | 凭 id 挂接：核验后把该帧按调用方指定地址映射进己方空间，登记第二端点 |
| `TunnelDispose(id)` | 主动拆除本端：解除本端映射、注销端点；双端皆亡时归还帧 |
| `TunnelNotify(id)` | 门铃：在对端的信号状态上提交 `DATA` 事件 |

id 为 48bit 随机数，防碰撞亦防猜测。Attach 与 Dispose 幂等性约束：同进程不得重复挂接同一条隧道（`ObjectNotAccessible`）；登记项数量有上限（`ReachLimit`）。

### 门铃

`TunnelNotify` 是唯一的通知通道：生产者写完数据后摇铃，消费者腾出空间后摇铃——一根铃铛两种含义，接收方醒来后读页内控制块自行分辨（电平语义的标准用法：**唤醒是提示，状态真值在控制块**）。不摇铃而纯轮询同样合法；摇铃只是免轮询的优化途径。

内核提交的是现成的信号事件（走粘滞余量 + 移交队列，见 [signal](signal.md)），不新增等待机制。

## 端点的信号位

每个端点是可等待对象，自带两位：

- **`DATA`**：消费式清除位——对端摇了铃。消费者的清铃前置条件与排空纪律由协议规定（Runnel 见 [runnel](runnel.md)：先排空、后清位、再转入等待）；
- **`PEER_CLOSED`**：终态位——对端已消亡或主动拆除。置位后持续可见至本端销毁，不可清除、不再变化。

## 所有权与生命周期

登记制（无能力系统前提下的最小正确方案）：

- **帧生命周期 = 双端全亡**。任一端退出或 Dispose 都**不**立即归还帧、也**不**触碰幸存端的映射——幸存端可能此刻正在访存，拆其映射等于惊杀，还帧则是 UAF。正确动作只有两个：注销死亡端点、给幸存端提交 `PEER_CLOSED`；
- 幸存端在 `PEER_CLOSED` 之后仍持有合法映射，访存安全，但页内内容不再有任何生产者保证；直到它自己 Dispose，帧才真正回池；
- 进程退出时内核清扫其名下全部端点（上述单端死亡的路径），这就是服务「干净被杀」时数据面资源不泄漏、对端不悬挂的机制保障。

id 经**消息面**转交：fs 场景中客户端发请求（message）→ 服务创建隧道 → 应答负载携带 id（message）→ 客户端 Attach。隧道句柄本身不随消息转移。

## 安全边界

访问控制 = id 的随机性 + 「id 只发给预期对端」的持有者自觉；机制层不做身份鉴权。服务级的鉴权（确认 attach 者是发起请求的那个客户端）由上层协议完成——服务只在响应自己收到的请求时才发出 id。

## 边界（不做什么）

- **无能力转移**：id 是弱凭据不是能力，可复制、可转述；精确到对象的权利裁剪不属于本机制；
- **无半关闭**：机制层的关闭是端点级全拆；流方向的结束表达由协议带内解决（Runnel 的 EOF 标记）；
- **不解析协议**：内核不知道页内是什么布局，「有数据」永远由对端摇铃声明；
- **Attach 地址由调用方指定**：用户 VA 分配器落地前的临时形态——进程清楚自己的映射布局，自报页对齐地址、内核校验冲突。此条随 VA 分配器里程碑重审。
