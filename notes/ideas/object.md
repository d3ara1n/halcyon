# 对象、Capability 与 Handle

对象代表内核管理的资源或关系。capability 表达对对象的授权持有，Handle 是该持有在进程表中的本地名字；对象身份只用于比较、协议验证和诊断，不能代替 authority。

## Handle 是本地名字

Handle 不作为跨进程凭据。复制数值不会产生新的持有；进程之间通过受权的能力运输交接 owner。本地名字失效后不得指向后来复用该位置的新对象。

## Capability entry

capability 关联对象及其操作权限；对象关系还可以包含唯一拥有、可复制引用或成功使用即消费等语义。权限衰减与对象关系分别表达，不能通过权限位伪造另一种关系。

公共能力机制拥有铸造、复制、移动、消费与释放。具体资源通过同一持有契约接入，公共层不识别线程、连接或某种映射来补齐清理。

## 所有权与终态

授权持有、已接受操作的使用责任、内核存储保活和对象终态是不同关系。一个 capability 消失不必终结既有操作，也不自动撤销其他主体已经取得的共享资源。

对象类型定义最后授权持有消失的含义；不同角色表达为不同对象类型，rights 只裁剪同一对象的授权；内存安全引用不直接决定业务寿命。资源来源跟随真实 owner，到安全退休时才归还。

## Lifetime 与观察

观察引用保留可查询的状态，不自动授予业务操作或延长被观察的活动。授权寿命与已接受交付的关系由 [message](message.md) 拥有；对象完成的通用观察由 [wait](wait.md) 拥有。

## HandleQuery

查询描述已经合法持有的能力及其关联身份、权限和状态。描述不是新的 owner，也不构成按裸身份重新打开资源的入口。

## MemoryPool 与 MemoryObject interface

资源账户表达分配来源与额度；内存对象表达可以独立于某个地址空间存活的 backing，映射表达地址空间对它的使用。关闭一份引用不收回其他合法 view 或独立派生资源。内存及其资金关系由 [mm](mm.md) 拥有。

## 调用者失约与所有权边界

用户进程可以关闭、转移、遗漏后续调用或终止。内核已接受的责任始终有稳定 owner，不依赖用户库的 Drop、调用约定或特定监督进程来维持正确性与回收活性。

安全用户接口区分描述、借用和真实持有，不能从可复制的数值建立第二份关闭权。业务事务与结果仍由对应用户态协议负责。

## 收束分层

Close 放弃一份本地持有，并把必要的后续责任交给内核。合法 Close 必成、有界，不等待完整退休、对端动作或业务完成；普通 owner 的 Drop 具有相同边界。

需要访问撤销屏障的 Unmap、需要业务结果的 Finish/Flush 与本地释放分别表达。Close 不证明旧地址翻译已经失效、共享对象已经销毁或数据已经持久化。

内核维护拥有实际退休和退款，宽工作在稳定 owner 下分批完成。进程终止后的资源回收同样由内核推进；用户态保留终止选择、完成观察及后续政策。物理资源在安全条件达成前不可复用。

## 两种跨表交付

消息中的暂存运输与向受控目标的直接交付具有不同存储关系。两者均必须保持 authority 和唯一处置责任，失败或放弃不能产生无 owner 的能力。具体入口、权限编码及对象限制由对象与 IPC 重构方案共同确定。

### 消息 transit

能力可以作为消息的一部分进入运输拥有体，再交给接收者；消息丢弃时由该拥有体释放未交付内容。

### 直接 grant

启动组装等场景可以直接把选定能力交给目标资源环境。创建关系本身不构成隐式继承授权。

## 身份、授权与平台根

PID 等身份只表达来源和诊断关系。平台资源、系统复位与初始管理 authority 来自可信引导，再由用户态管理者显式分发；普通进程不能通过身份数值取得它们。

## StartupBlock

普通启动数据与能力交付属于 launcher 和目标程序之间的约定；内核只负责受权组装和执行发布。引导关系由 [bootstrap](bootstrap.md) 拥有。

## 边界

内核对象机制提供授权、持有、运输、释放和完成观察。文件路径、业务权限、服务注册、撤销政策及付款组合由用户态领域解释。具体对象清单与实现取舍记录在[capability 重构计划](../../plans/todo-2026-09-28-capability-last-reference.md)。
