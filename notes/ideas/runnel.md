# Runnel

Runnel 是 Halcyon 的官方流式数据交换协议：运行在[隧道](tunnel.md)页上的**单工 FIFO 字节流**。本规范与[共享内存协议公共契约](shared-memory.md)共同构成互操作要求；固定宽度、little-endian、对齐、Acquire/Release、角色视图、不信任对端和 Broken 规则均为规范义务。

## 页布局

一页 4 KiB，固定划分为 128 B 控制块和偏移 `0x080–0xFFF` 的 3968 B 环形数据区，容量 `CAP = 3968`。

| 偏移 | 类型 | 字段 | 唯一写者 |
|------|------|------|------|
| `0x00` | 对齐原子 `u32` | `MAGIC = 0x314C4E52`（小端字节为 `RNL1`） | 创建者，初始化一次 |
| `0x04` | `u16` | `VERSION = 1` | 创建者，初始化一次 |
| `0x06` | `u16` | 保留，必须为零 | — |
| `0x08` | 对齐原子 `u32` | `head`：累计写入字节数 | 生产者 |
| `0x0C` | 对齐原子 `u32` | `tail`：累计读取字节数 | 消费者 |
| `0x10` | 对齐原子 `u32` | `eof`：流结束标记（0/1） | 生产者 |
| `0x14–` | — | 保留，必须为零 | — |

游标是自由计数而非数组下标，差值按模 2³² 回绕：`used = head -% tail`，且必须在 `0..=CAP`。空当且仅当 `head == tail`，满当且仅当 `used == CAP`。

创建者先写版本、保留区和初始控制字段，最后以 release `store` 发布原子 MAGIC；attach 方先以 acquire 读取 MAGIC，命中后验证版本与全部初始不变量，才取得角色。创建者一律写零保留区；同版本读取者忽略保留内容。锚点、版本或不变量失败即进入 Broken。

## 读写、EOF 与验证

生产者独占 `head` 和 `eof`，消费者独占 `tail`；双方不得以普通写或读改写访问对方字段。生产者先写数据，再 release 发布 `head`；消费者 acquire 读取 `head` 后读数据，再 release 发布 `tail`；生产者 acquire 读取 `tail` 后才覆写。

双方保存最近一次已接受的对端游标。生产者只接受 `tail` 在模 2³² 意义下前进不超过此前尚未消费的字节数；消费者只接受 `head` 前进不超过此前剩余容量。更新 shadow 后还必须满足 `used <= CAP`，每次实际复制长度也必须 `n <= CAP`；任一条件违反即 Broken。

生产者在最后一次 head 发布后以 release 置 `eof = 1`，此后不再写入。消费者先 acquire 读取 eof；只有观察到一时，才 acquire 读取 head 并判定已排空。已排空且 eof 为一才是正常 EOF。`PEER_CLOSED` 或页内错误不是 EOF，必须停止传输并进入 Broken。

## 门铃与阻塞循环

会进入阻塞等待的封装在每次写入、腾出空间或发布 EOF 产生正进展后，都必须在等待或返回前通知对端；批量实现至少保证空到非空、满到非满和 EOF 等关键转换得到通知。双方明确约定永不阻塞的纯轮询模式可以省略门铃。门铃只提示状态改变，真实可读量和可写量始终来自控制块。

阻塞角色反复执行：检查控制块能否继续；不能则 `TunnelAcknowledgeData`、重新检查；仍不能才以 WaitMany 等待 `DATA | PEER_CLOSED | CLOSED`；醒来后从头检查。消费者只在读至空后确认 DATA，生产者只在确认无空间时等待腾空提示。确认后的重查与 WaitMany 安装闭环覆盖全部竞态。
