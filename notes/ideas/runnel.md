# Runnel

Runnel 是 Halcyon 的官方流式数据交换协议：跑在隧道（[tunnel](tunnel.md)）页上的**单工 FIFO 字节流**。本文是规范性规格——任何两个互不见源的实现，凭纸面条款即可正确互操作；凡标注「规范义务」的条款不可裁剪。

## 页布局

一页 4KiB，固定划分为控制块与环形数据区：

| 区间 | 偏移 | 内容 |
|------|------|------|
| 控制块 | `0x000–0x07F`（128 B） | 下表字段 |
| 数据区 | `0x080–0xFFF`（3968 B） | 环形缓冲区，容量 `CAP = 3968` |

控制块字段：

| 偏移 | 类型 | 字段 | 写者 |
|------|------|------|------|
| 0x00 | u32 | `MAGIC = 0x52_4E_4C_31`（"RNL1"） | 创建方一次性 |
| 0x04 | u16 | `VERSION = 1` | 创建方一次性 |
| 0x06 | u16 | 保留（零态） | — |
| 0x08 | u32 | `head` —— 累计写入字节数 | **仅生产者** |
| 0x0C | u32 | `tail` —— 累计读取字节数 | **仅消费者** |
| 0x10 | u32 | `eof` —— 流结束标记（0/1） | **仅生产者** |
| 0x14– | — | 保留（零态） | — |

游标是**自由计数**而非数组下标：比较与差值一律用模 2³² 回绕运算（`used = head -% tail`），计数越过 2³² 后语义不变。容量不进 ABI——对端从页大小自行推导。

## 不变量

- `used = head -% tail ∈ [0, CAP]`；
- 空 ⇔ `head == tail`；满 ⇔ `used == CAP`（单写者原则使方向天然可辨，无需牺牲一格判满）；
- 生产者是 `head` 与 `eof` 的唯一写者，消费者是 `tail` 的唯一写者——任何字段都不需要原子读改写。

页由机制层以零态交付，零态本身即合法初始态（空流、未结束）；`MAGIC/VERSION` 由创建方在 Create 返回后、首次传输前写入一次，作为布局版本的锚点。

## 内存序（规范义务）

RISC-V 弱内存序下，跨端可见性只靠 acquire/release 配对保证。以下顺序是协议正确性的构成部分，不是实现建议：

- 生产者：先写数据字节 → 再以 **release** 语义发布 `head`；
- 消费者：先以 **acquire** 语义读 `head` → 确认可读量后读数据字节 → 读毕以 **release** 语义发布 `tail`；
- `eof` 的置位 release 于最后一次写数据的 `head` 发布之后（或与其同批），消费者对 `eof` 的读取 acquire 于 `head` 之后。

具体指令形态（fence / aq-rl 后缀）是实现细节。

## 操作规则

生产者写（伪代码，消费者读对称）：

```text
write(buf):
    loop
        tail  := load(tail, acquire)
        free  := CAP - (head -% tail)
        n     := min(free, len(buf))
        if n == 0:
            wait_for(SPACE_AVAILABLE)   // 阻塞形态；或轮询重试
            continue
        store buf[..n] into ring at head % CAP
        head +%= n ; store(head, release)
        notify_peer()                   // 摇铃纪律见下
        buf = buf[n..] ; if empty: return
```

消费者读完一批并排空后必须摇铃（腾出空间的声明），否则生产者将永久等待。

### 摇铃纪律（规范义务）

- 唤醒是提示不是账目：多次摇铃合并为一次未决状态是合法且预期的；
- **消费者的清铃前置条件是控制块已排空**：读到空为止才许清 `DATA` 位、转入等待。清铃前发生的所有摇铃都已在粘滞位里，合并不丢事件；违反此条即可能死等；
- 允许批量合并摇铃（多批写一次铃）；允许纯轮询不摇铃（盲等模式，性能自担）。

## 流结束（EOF）

机制层无半关闭，流的逻辑结束由带内表达：生产者写完最后的数据后将 `eof` 置 1（release）。消费者观察到「已排空 且 `eof == 1`」即流正常终止。此后生产者不再写，消费者不再读。

对端的非正常消亡由机制层的 `PEER_CLOSED` 终态位表达；该位置位后页内内容不再有生产者保证，协议实现应立即停止传输并上报错误。

## 分工总表

| 关注点 | 归属 |
|--------|------|
| 共享页分配、映射、生命周期、PEER_CLOSED | 隧道机制（内核） |
| 到达/腾空的阻塞唤醒（DATA 位）、门铃通道 | 隧道机制 + 信号面 |
| 页布局、游标推进、内存序、EOF、摇铃时机 | 本协议 |
| 连接建立的身份鉴权（谁可以 attach） | 上层服务协议（如 FAL） |
