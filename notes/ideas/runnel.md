# Runnel

Runnel 是运行在 [Tunnel](tunnel.md) 共享 backing 上的单工 SPSC 字节流协议。生产者、消费者、共享控制状态与本地映射共同形成一条连接；记录和独立缓冲交接由 [BufferQueue](buffer-queue.md) 表达。

## 角色与进展

生产者发布字节，消费者读取并归还空间。双方分别持有自己的进展和对端状态的已验证观察，共享字段不能直接变成本地可信地址或任意内存视图。

每侧协议准备完成的 Start 与内核 Endpoint 已接入是不同事实。上层可以等待 Started、可读/可写以及 EOF 后的消费完成，不能用数据量或内核 PEER_ATTACHED 互相替代。

## 数据与完成

Runnel 的 EOF 表达数据端的结束，Endpoint 关闭或协议错误不等于正常 EOF。已经发布或消费的进度不能因后续通知失败而撤回；错误结果须保留已经完成的字节数。

文件后端接受、持久化和业务最终结果由上层协议解释，Runnel 不把字节运输完成转换成业务成功。

## 门铃、等待与退出

门铃只提示重读共享状态。无进展时，角色确认 DATA 并完整复检条件，再通过单对象等待或持久来源登记停驻；跨多次等待保留原绝对期限。通知策略必须支撑所承诺的阻塞行为，不能仅凭一次观察到的空/满边沿推断不会丢失唤醒。

Endpoint、View、协议角色和执行框架的来源登记分别持有责任。退出先结束观察关系，再按映射和 capability 的各自合同释放；映射失败保留实际清理 owner，不能把普通 Close 的必成语义泛化到 Unmap。

公共共享访问边界见 [shared-memory](shared-memory.md)。当前协议布局、版本、Start、游标算法、失败返还与实际消费者由 [Runnel 实现](../impls/runnel.md)说明；这里不另维护一份线上字段表。
