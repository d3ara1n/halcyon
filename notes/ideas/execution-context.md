# 执行环境

执行环境把平台 hart、用户线程与内核边界连接起来。它只承认经过平台事实核验的 hart，并保证线程全部用户可见持久状态在可运行 hart 上得到完整隔离。

## Hart 身份与准入

硬件 hartid、内核稠密 slot 与拓扑层级是三个不同概念：hartid 属平台 ABI，slot 属内核容器索引，拓扑只服务 affinity、电源与共享资源政策。ISA、MMU 和扩展能力必须逐 hart 读取，不能从编号或拓扑推断。

进入统一调度环境的 hart 必须满足内核基线并支持系统选定的地址翻译模式。不能满足者不进入该环境；若未来需要使用，应作为独立 AMP 执行域设计，而不是让共享内核映射建立在不成立的能力交集上。

## 用户执行需求

用户执行需求来自可执行映像的正式 ABI 元数据，不由程序名或服务角色推断。每种公开档位必须满足三者之一：

1. 完整保存和恢复其全部持久状态；
2. 由已核验的硬件 gate 保持关闭；
3. 不允许该线程进入缺少隔离能力的 hart。

GPR、PC、浮点、向量、控制状态和未来 TLS 等用户可见持久状态都属于线程，不属于 hart 或进程的临时缓存。新档位只有在上下文所有权、硬件准入和真实负载验证同时闭合后才能开放。

## 调度域

调度域按“满足同一组执行需求”的签名划分 hart。与已建模需求无关的硬件差异不产生新域；新增需求只会细化既有划分。hart 的域归属在启动期冻结，进程的兼容域绑定在首次发布执行时冻结，线程经进程持有该归属。

多个域兼容时，默认选择能力最弱的兼容域以保留稀缺能力；显式 affinity 与跨域迁移属于后续政策 ABI，接入边界由结构固定：进程在 Start 冻结的是不可变执行需求签名与初始放置，未来 affinity 只改放置（可细到线程）不改需求；迁移是单一归属容器之间的显式搬移，不破坏「线程任意时刻恰处于一个容器」；wake 门铃以线程实际进入的类所在域为准，不随进程绑定移动。调度类只决定域内先后次序，不承担硬件兼容判断。

## Trap 边界

trap 来源由硬件状态判定，不依赖可被用户伪造的内存标记。进入内核时必须先保存所有尚未可安全复用的用户寄存器；返回用户态前必须恢复完整线程现场并建立确定的 CSR 稳态。系统调用只约定返回寄存器可变化，其余用户寄存器均保持。

线程离开用户地址空间后，内核必须在宣布 active-hart 离场前切回正式内核地址空间并完成本地地址翻译同步。该边界是进程回收可以释放页表的前提，不能分散到每一种终止来源各自维护。

实现细节见 [`../impls/execution-context.md`](../impls/execution-context.md)，任务与域绑定见 [`task.md`](task.md)。

## 用户态平台入口

用户 ELF 的正式入口采用不返回的 `_start`。入口地址仍由 ELF 提供，内核不认识符号名或 runtime 包名。内核建立已准入的执行 profile、PC、栈和两项整数参数；用户平台适配器在调用任何普通 Rust/C 函数之前完成进程映像要求的寄存器准备。入口线程适配归 runtime，运行期线程 trampoline 归 libthread，共同使用 user/platforms 的平台契约。

| 项目 | 内核/装载方的责任 | 用户平台入口的责任 |
|---|---|---|
| PC | 验证可执行映射，绑定线程执行需求 | 进入显式无编译器序言的适配段，不依赖 main 包装函数 |
| SP | 交付可用且 16 字节对齐的用户栈；先有 backing，再允许执行 | 保持对齐；不切换成无 owner 的临时栈，不使用 red zone |
| a0/a1 | 入口线程为 StartupBlock 基址/字节数；运行期线程为其显式上下文参数 | gp 准备不得破坏参数，入口线程交 runtime 校验，运行期线程交 trampoline |
| gp | 新出生现场不承诺继承调用者 gp | 每次入口从本映像的 `__global_pointer$` 初始化，包含所有新工作线程 |
| tp | 当前不交付 TLS/TCB，出生为零 | 当前保持无 TLS；不将零当作有效 TLS 基址 |
| ra | 没有合法调用方返回地址 | 所有入口最终调用受控 Exit，不 ret 到零或随机地址 |
| 浮点 | 按 profile 设置 gate 并初始化/恢复完整 FPR/fcsr | Base64 入口不执行 F/D；D64 不在用户代码重复改写内核 gate |

RISC-V psABI 要求标准过程入口和过程执行中 SP 保持 128 bit 对齐，gp/tp 不作通用临时寄存器；这些机器约定不要求引入 POSIX。a0/a1 的启动语义属于 eRhino 自有 ABI，不能由 argc/argv 的 Rust/C main 签名暗示。

共同链接布局必须定义本映像的 `__global_pointer$`，由布局依据 small-data 可寻址窗口选择位置；初始化在首个符号数据访问之前完成，采用 psABI 推荐的 `.option push` / `.option norelax` PC-relative 装载序列 / `.option pop`。不能依赖某个链接器版本在未定义该符号时恰好不生成 gp-relative 访问，也不能只为入口线程初始化 gp 后让其它线程从零开始。实现可共享平台汇编模板，但 libthread 与 libruntime 都不得通过相互依赖取得该知识。

首/工作入口仅做必要寄存器设置，然后以正常 psABI 跳转或调用相应 `extern C` Rust 桥接函数。工作入口的地址是单一平台 trampoline，具体任务通过稳定 packet 中的函数入口表达，避免为每个 F/T 重复定义全局汇编符号。函数入口由 libthread 在准备时构造，原始任意地址仍是 unsafe；packet 不因为保存函数指针就丢掉类型与资源证明。

Base64 使用 RV64IMAC/LP64，FS 关闭；D64 使用相应支持 F/D 的执行需求与 LP64D，FPR/fcsr 是内核拥有的持久线程状态。语言环境不改变 thread/hart 的 profile，也不以父线程的浮点寄存器内容代替新线程初态。当前 ELF admission 拒绝 PT_TLS，不提供 TLS 或动态链接；将来支持 TLS 须同时闭合 ELF 模板、每线程 TCB、tp、初始化/析构及所有入口路径。
