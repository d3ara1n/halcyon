# 内核边界

内核只拥有必须由特权级统一强制的短路径机制：执行环境、地址空间隔离、线程调度、对象与 capability、IPC 转运、等待与硬件资源根。文件系统、进程监督、设备匹配、服务发现、重启和资源分配政策均在用户态服务中完成。

## 协作式内核

微内核边界与协作式执行互为因果：内核路径恒短，因此 S 态执行流不需要抢占、阻塞或内核线程。trap 进入内核后完成一次有界操作，再返回用户态或切换到另一用户线程；长工作拆成用户态政策循环与可恢复的有界内核批次。

若某项需求看起来必须依赖内核抢占、内核睡眠或后台内核线程，首先应重新判断工作归属，而不是扩张中断模型。调度发生在用户态 trap 的返回边界，S 态中断只在内核离开后处理 pending 来源。

## 机制与政策

内核机制只回答“谁持有 authority、一次操作能否原子完成、状态如何等待、资源如何有界收束”；用户态政策回答“授给谁、何时关机或重启、怎样遍历一棵管理树、如何组合服务”。

同一原则适用于：

- 进程终止：内核冻结终因并提供 REAPABLE/Drain，管理者组合递归 JobKill；
- 文件系统：内核运输消息和 Handle，provider 解释路径与权限；
- 设备：内核铸造平台资源 capability，资源服务选择驱动与租借政策；
- 系统复位：内核验证 primordial capability 并调用平台后端，用户态决定关机时机与收束政策；
- 大数据 IPC：内核建立共享映射与门铃，用户态协议解释页内数据。

## 有界路径

用户可触发的单次内核调用必须有结构性工作上界。宽度可能增长的工作以游标、稳定 token 或用户态遍历表达；失败和中断后由同 authority 的管理者继续，不把进度绑定到某个调用线程。

对象关闭只承担固定上界的叶子收束；容器级资源释放走显式、可预算的 drain。内存不足是普通可恢复错误：提交前完成全部可失败预留，提交后不分配、不回滚。
已经 Commit、且只能由内核完成的特权状态转换不能伪装成用户态政策，也不能塞进一次完成回调。超过单次预算的完成义务以显式 work debt 和稳定游标存在，由有明确唤醒所有者的 trap 安全出口逐批推进；每批工作有结构上界，未完成债务保持可达并再次触发安全点，最终一批才发布对外完成。它不需要内核线程，也不允许因调用线程消散、进程终止或系统暂时空闲而丢失。work debt 的活性由结构保证：owner 恒为发布最后确认的 hart，而该 hart 在发布时必然正执行于安全点，债务发布从不依赖跨 hart 唤醒；idle 入睡前对 Pending 的双重检查与运行 hart 的周期性安全点覆盖其余路径，self-IPI 失败的残余窗口属于已声明的平台 admission 契约违反。

## 状态与唤醒

共享状态按归属分层：hart 私有状态由执行点独占，对象状态由对象锁保护，全局状态只保存真正的全局事实。每个等待来源都必须有明确的唤醒所有者：本 hart 的确定到期点、其他 hart 的门铃请求，或设备的中断请求。没有 runnable 工作和期限时，hart 只进入 WFI；局部或全局空闲都不表达系统生命周期意图。
