# 内存模型

内存管理连接物理库存、资金来源、backing、地址空间与硬件翻译。映射几何、实际使用和物理存储分别表达，具体事务及退休合同由[内存计划](../../plans/todo-2026-10-01-memory-redesign.md)拥有，当前实现见 [mm](../impls/mm.md)。

## 物理供给与分配

平台描述提供可用与保留内存的输入，规范化后的供给区分系统储备、用户库存和设备专用范围。内核堆、用户物理库存与进程用户态分配器各自管理所属资源，不共享隐式透支或回退政策。

物理 extent 表达连续帧的所有权，backing 可以组合多个 extent。普通映射不要求物理连续；DMA 等消费者的连续性和可达性需求由对应资源契约表达。动态与 reusable 保留区的接通条件见[保留区计划](../../plans/todo-2026-09-platform-reserved-memory-lifecycle.md)。

## 地址空间与页表

AddressSpace 汇集区域几何、映射来源、修改责任、同步代次与退休进度。Process 持地址空间引用，组装、运行期修改与退出共用这一机制。

`page_table` 拥有分页模式和硬件表结构原语，`memory_space` 拥有纯逻辑几何与修改协议，内核 `vm` 连接实际 owner、存储、锁、硬件执行与维护工作。区域账本描述映射关系，页表是硬件投影。

分页模式按地址空间选择，并受可执行它的 hart 集合约束。更宽模式涉及地址布局、内核共享映射和调度兼容性；Sv48/Sv57 的接通由内存计划单独承接，当前实现使用 Sv39。

## Backing 与 View

Backing 连接稳定存储身份、物理 extent 与原资金来源。实际使用由覆盖逻辑区间的 use 表达，存储引用本身不代替使用关系；匿名 View、共享 MemoryObject 和 DMA 可以持有不同范围的使用。

View 表达地址空间内的映射及其权限上限，持有对应来源的使用关系。Endpoint 等能力可以授权建立 View，能力关闭与 View 解除分别承担各自责任。MMIO 是独立映射来源，与 RAM 共用地址空间几何和修改机制。

CPU View 与 DMA mapping 分别持有使用和写许可。CPU 翻译同步不能证明设备已停止访问；各方退出自己的使用关系后，backing 才能按范围退休。

## 资金与容量

Pool 表达页与 metadata 两个独立资源维度，资源和已接受操作持有对应费用。能力运输改变授权可达性，既有存储仍由原来源付款。资源归还与费用退款由同一责任链连接。

实际存储计费与不可信域之间的硬容量隔离是不同能力。隔离边界、触发条件和验证门由[预算计划](../../plans/todo-2026-09-14-kernel-memory-budget.md)拥有；用户态资源管理者组合资金、执行和设备授权。

## 修改、故障与退休

Map、Unmap、Protect 经地址空间提交意图。准备持可取消资源，提交后责任由内核稳定持有；页表发布、同步确认、实际释放与结果交付各有对应完成事实，通过有界维护连接。

Guard 表达没有 backing 的保留区域。用户访问故障与内核访问用户内存分属各自入口，修改期间的 fault 由地址空间事实决定如何继续；具体 uaccess、并发修改和结果租约合同见内存计划及实现说明。

跨 hart 同步连接页表发布、执行进入与旧资源退休。运输属于发起修改或退休的稳定工作，调用线程消散不使已提交责任丢失。整空间退出还需收齐执行离场与既有操作的责任。

## 可执行内存

可执行发布关联 backing 的写许可与代码代次。CPU 和设备写者共同影响是否可以发布为可执行；解除映射、同步和写许可归还共同构成退休关系。

MemoryObject 的可执行状态通过[通用等待面](wait.md)观察。映射权限、seal、硬件 fence 与新代码版本的详细合同由内存计划及 [MemoryObject 实现](../impls/memory-object.md)拥有。
