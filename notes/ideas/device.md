# 设备体系

设备体系组合硬件事实、资源 authority、设备绑定、驱动运行与功能服务。内核提供特权资源的隔离和撤销机制；用户态解释设备、选择驱动并组合业务。驱动是持有特定能力的普通进程。

## 设备、绑定、供应与功能

| 概念 | 表达的关系 |
|---|---|
| 设备实例 | 由受权来源登记的设备及其属性、拓扑和存在性 |
| Binding | 某一轮对设备的占用与使用关系，与设备实例身份分开 |
| Provision | 供应方为该轮使用准备的资源与受限协议入口 |
| 资源 capability | 对 MMIO、IRQ、DMA 或父总线会话的实际操作权 |
| 功能会话 | 应用可消费的键盘、串口、块设备、网络或传感器协议 |

设备描述、驱动进程存活、功能可用与硬件可安全再分配是不同事实。名称、位置和描述中的地址不产生 authority。

## 领域模块与运行角色

- libdevice 拥有设备身份、登记、绑定、供应和功能关联；srv_device 承载设备目录与平台供应的组合。
- libdriver 拥有驱动声明、选择、激活与运行支持；srv_driver 组合这些知识、设备协议和进程管理。
- 具体总线与功能库拥有自己的协议和硬件知识，例如 libpci、libusb、libhid。驱动进程消费这些库以及受托的资源或父总线会话。
- init 组合系统允许的映像、管理域、付款来源与监督关系；普通客户端通过功能协议使用设备。

库划分表达知识边界，进程划分表达授权、故障和执行边界。一份驱动进程可以承载多个 Binding；每轮绑定仍保持独立身份与控制关系。库的链接关系本身不授予能力或启动运行体。

## 三类关系

拓扑描述控制器、总线、端口与子设备的连接；供应关系描述父总线会话以及时钟、复位、供电、引脚等依赖；隔离与恢复关系描述共享 MMIO、IRQ、DMA 或复位域的影响范围。三者互相关联，但不合并为一棵能表达所有含义的树。

设备编号不同不代表硬件可独立分配。固定板级设备、运行期枚举和组合功能使用共同的设备概念，各自的资源与协议由对应领域解释。

## 控制面与数据面

设备管理组合登记、选择、占用、准备、激活、观察和停止。应用的数据路径通过功能服务、父总线或设备队列到达硬件，不经设备管理服务逐请求转发。

BindingUse、子 Registrar、Provision 与激活观察连接同一轮的参与者。硬件停止事实由持相应能力的执行者产生，管理者据此组合资源收束；进程终态不能替代设备停止或 DMA 安全。

## 内核资源与用户态协议

MMIO 资源限定映射范围与访问权限；IRQ 使用对象连接来源领取、确认与等待；DMA 映射连接 MemoryObject backing 和设备可访问寿命。用户态通过 libkernel 使用这些机制，驱动负责寄存器、描述符、队列和总线事务。

CPU 地址、物理地址与设备地址属于不同空间。软件流或缓冲交接不自动提供 DMA 保活与硬件隔离；IOMMU、非一致缓存和共享中断等能力由平台合同及对应实现提供。

## 发现与系统组合

设备、驱动及功能视图使用 [OAL](oal.md) 的发现表示，各领域保留自己的权威状态。服务注册、设备占用和功能调用可以组合，但发现目录不成为第二份设备生命周期。

启动关键能力直接交付；运行期发现依赖已经建立的入口。局部设备停止与[系统关机](../../plans/todo-2026-09-system-shutdown-orchestration.md)相互衔接，监督与恢复由[服务装配](../../plans/todo-2026-10-07-service-assembly.md)组织。

详细身份、授权、状态转换、停止证明、平台范围与验证边界由[设备计划](../../plans/todo-2026-09-device-system-design.md)拥有。更多总线、复合设备、共享供应及隔离能力仍沿这些领域关系扩展，其需求与接通条件由该计划登记。
