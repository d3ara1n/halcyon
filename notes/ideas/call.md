# 内核调用

System Call 连接用户线程与特权机制，Remote Call 连接不同 hart 上的短内核动作。两者使用协作式、有界的内核执行，不产生可睡眠的独立内核线程。

## System Call

短调用直接交付结果；需要多步准备的请求由原线程执行责任承载；需要等待的调用保存续体及来源关系。请求推进、等待和最终用户返回分别由其执行 owner 负责，不能由来源回调绕过线程的退出边界。

提交前的准备可以失败并回滚，已提交的特权工作由稳定内核 owner 继续完成。调用者退出可以结束回复关系，但不丢失已接受的发布、回滚、退休或退款责任。

普通 capability Close 放弃本地持有并交接必要的后续责任。映射撤销、访问同步与业务完成使用各自明确的操作和观察边界，不能把普通 Close 当作这些完成屏障。

## 时间、观察与结果交付

公共时间使用单一单调时间域和绝对 Deadline。WaitOne 观察一个对象的状态，WaitSet 组合多个持久来源；等待只提示重新判断条件，不授予业务操作权。

输入校验、可回滚准备、用户输出和不可逆提交必须保持所属操作的顺序。等待结果与异步业务工作分别持有责任；映射结果的交付由内存合同定义，不依赖失效的用户指针或调用者再次发起 syscall。

## Remote Call

远端运输由请求所属的业务拥有体提供承载，IPI 只提示目标 hart 检查已经发布的工作。目标有界执行硬件动作，归还运输承载并确认完成，再通知原业务 owner；运输不拥有地址空间事务或资源释放政策。

TLB/指令同步使用空间与事务身份关联远端完成。完成确认、运输槽可复用和 backing 可释放是相互关联的不同事实；门铃失败按已确认的平台停止政策处理，不伪造成功或撤回已提交责任。
