# 信号

信号是 IPC 的**事件面**：以对象上的状态位表达「某件事发生了」，配合阻塞等待实现事件驱动。三面分工中事件归信号：数据走消息（[message](message.md)），大块流式数据走隧道（[tunnel](tunnel.md)）。

## 可等待对象

信号状态不是独立机制，而是**内核对象的一个切面**：每个可能产生事件的对象自带一份信号状态（小掩码 + 等待者队列，见下）。当前可等待对象及其位义：

| 对象 | 位 | 义 |
|------|-----|-----|
| 进程（自身） | `TERMINATE (bit0)` | 终止请求 |
| 进程（自身） | 其余位 | 用户协议自定义区 |
| 邮箱（自身） | `NONEMPTY` | 有未取消息 |
| 隧道端点 | `DATA` | 对端写入数据 |
| 隧道端点 | `PEER_CLOSED` | 对端已关闭（终态位，持续可见至对象销毁） |

引用沿用各对象既有的标识（自身进程 / 自身邮箱 / 隧道端点号），不另设平行对象系统。等待表达：

```text
SignalWait( &[
    ( SELF_PROCESS, TERMINATE ),
    ( MY_MAILBOX,   NONEMPTY ),
    ( TUNNEL(37),   DATA | PEER_CLOSED ),
])
→ 返回：( 命中对象, 命中位 )
```

## 状态机：粘滞余量 + 移交队列

每份信号状态由两部分组成：

- **粘滞余量**（mask）：尚无人消费的事件，按位或缓存；
- **等待者队列**（FIFO）：阻塞在该对象上的线程，按阻塞先后排序。

到达规则（投递方只做这一件事）：

- 队列非空 → 事件**直接移交**队头线程：定向唤醒并交付命中结果，对应位自粘滞余量清除；
- 队列空 → 事件按位或并入粘滞余量，留待后来者。

等待规则（`SignalWait`）：关注位与粘滞余量有交集则立即返回并清除交集；否则入队尾、转 Waiting（登记内核请求，见 [call](call.md)）。

由此得到三条性质：

1. **公平由结构保证**：并发消费者按入队顺序获得事件，内核不做任何挑选——公平性来自 FIFO 数据结构性质，而非记账字段或调度偏好；
2. **无惊群**：一次事件恰好唤醒一个等待者，其余继续安睡，不存在被吵醒后扑空重睡；
3. **迟到者不落空**：无人等待期间的事件缓存在粘滞余量里，后来的等待者立即命中。

## 投递语义

信号无负载、不排队：一个位只表达「有事」，同类事件的多次发生合并为一次未决状态；计数与数据语义由消息面承载——要排队就发消息。

匿名性：接收方只见「哪个对象哪些位置位」，不见投递者身份。需要感知发送者的场合（如服务识别客户端），由消息面的 sender 字段承担。

## 终止语义

`TERMINATE` 表达的是**请求**而非强制：是否退出、何时退出由进程自行决定；强制终结不经信号面，直接走进程回收通路——被回收方无需配合。分层理由与 fault 处理一致：协商用信号，强制用回收。

## 分发层：rinlib 运行时

内核只负责置位、移交与唤醒；信号到用户代码的分发由 rinlib 的运行时（rt）承担：

- `rt::init` 时 spawn 一个**监听线程**：循环 `SignalWait` 于 `{ (SELF_PROCESS, TERMINATE), ... }`，命中后在**本线程自己的栈上**普通调用已注册的回调（终止处理的默认实现为置 stop 标志或直接退出进程）；
- 与内核注入的本质区别：回调发生在明确的线程、明确的调用点，内核从不改写任何执行现场——没有现场备份、没有 sigreturn trampoline、没有可重入问题；
- 即时性由结构保证：SMP 下监听线程并行于主逻辑；单核下时间片轮转同样及时；
- 主程序零改动获得事件驱动体感；不使用监听线程的程序以显式检查点（轮询各对象信号态）自行替代，两者不互斥。

进程退出约定：**最后一个线程退出即进程回收，主线程无特权**；「main 返回即结束整个进程」是 rt 层约定（main 包装返回时调用进程级 Exit）。

## 不做什么

- **无 handler 注入**：不存在内核改写用户执行现场跳转处理函数的机制。POSIX 式信号的整套成本（现场备份、trampoline、可重入性、async-signal-safety）被整体拒绝；微内核生态（seL4 notification、Zircon signals、QNX pulse）一致收敛于显式等待 + 用户态分发。
- **无排队、无计数**：事件不携带数据也不缓存次数，数据面的事归数据面。
