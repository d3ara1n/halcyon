# 文件系统

文件系统是用户态服务体系：任何进程都可以作为目录提供者，以 [FAL](fal.md) 固定宽协议应答路径请求；内核不含路径查找、根文件系统、挂载点或文件属性语义，只提供消息、Handle、隧道和等待机制。命名空间没有中央权威：每个进程持有一张私有的前缀路由表，把路径解析委托给对应提供者。

## 命名空间与挂载

命名空间由启动授权组装：授权方以成对的（名字前缀, 目录 Handle）交付初始路由表，运行中的扩充只能来自显式的 Handle 交付。挂载不是协议对象，没有全局挂载表和权威根目录；视图随交付产生、随 Handle 关闭消亡，不被其他进程的重挂载改写。路径规范化由客户端库执行，提供者把收到的路径当不可信输入自校验（详见 [FAL](fal.md)）。服务的发布、发现和撤销以授权后的 Handle 属性表达（详见 [FAL](fal.md)「服务发现」与 [service](service.md)）。

## 操作面

节点检查、目录枚举、元数据读取或修改、创建、删除、移动、复制和打开流都是 FAL RPC kind。小型请求和应答使用消息；大块内容通过隧道传输。协议规定固定宽字段、字节序、版本、长度、错误和分页，避免把本机结构体布局或内核地址作为接口。

## 生命周期

服务的邮箱关闭或隧道对端关闭是可等待的对象终态。客户端库根据协议把这些终态转换为调用失败，并可按策略重新发现或连接新服务；已授出的 Handle 不因目录名称撤销而自动失效。
