# FAL 扩展操作与一致性能力

> 状态：等真实消费者触发的未来计划。本文件只拥有基本 FAL 范围之外的能力，不承接当前正式 grant、Open、Watch、注册/发现、同域 Move 或普通 Copy；这些由 [`FAL 整体计划`](todo-2026-09-fal-service-capabilities.md) 唯一交付。

## 当前范围与延后理由

基本 FAL 支持稳定节点授权、非快照的单工普通流、允许部分结果的 Copy、单 provider 的直接成员 Watch 和明确的最终完成；不默认承诺持久化、递归事务或能力复制。该范围能独立闭合，下面的扩展尚无真实消费者，提前实现的存储/协议成本高，不能为此把基本操作描述成语义不完整的临时实现。

## 唯一能力清单

| 能力 | 现状、目标与位置 | 触发与完成标准 |
|---|---|---|
| 递归目录 Copy / Delete | 基本 Copy 仅普通流和不含能力的数据属性，Delete 拒绝非空目录。目标是在 `libfs` 的显式有界任务中定义遍历、一致性、取消、部分树和资源回收；方向归 `ideas/fal.md`。 | 出现备份、安装或目录树管理消费者；固定并发修改和失败政策，跨 provider 大树/循环/取消/部分目标都有验证，不能以用户栈递归调用充当有界任务。 |
| Snapshot / 原子替换 / 持久完成 | 普通读取不保证快照，Finish 只表示后端接受字节。目标由 provider 能力声明和独立操作表达快照、原子替换及持久性；落 `libfal`、后端与 `libfs`。 | 真实存储后端或需要稳定映像/持久配置的消费者；先冻结 crash/取消语义和资源来源，再证明旧读者、替换冲突、持久失败与恢复。 |
| Capability 属性 Copy | Repeatable read 和 affine Take 已在基本专题内；通用 Copy 不复制含 Handle 的属性。目标是显式声明可复制 authority 与出口政策，禁止把 affine 值当可重复资源；落 `property.rs` 和对应 exporter。 | 需要复制含能力的配置/记录；每种出口的权限衰减、别名、重复/一次性区别和失败所有权有端到端证据。 |
| 递归/跨 provider Watch、可重放事件 | 基本 Watch 是本 provider 节点/直接成员的 OR 失效提示。目标另定义事件身份、负载、日志/快照恢复、容量溢出和跨 provider 订阅图；落 libfal/libfs，数据面可以采用独立日志协议。 | 出现索引、同步或审计消费者；有溢出重同步、服务重启、取消整张订阅图和历史保留边界，不能只扩 Notification 位数。 |
| append 与组合打开政策 | 基本 Open 使用现有节点和显式 offset，不隐含 append/truncate/create。目标是 provider 原子分配 append 位置，以及明确的 create/open/truncate 组合线性化；落 FAL Open wire/后端。 | 真实日志/文件工具需要；并发写、目录替换、创建冲突、超时未知结果和部分完成有独立契约。 |

## 自然顺序与归档

基本 FAL 整体交付 → 出现真实消费者并选定所需能力 → 先闭合对应存储/授权/日志前置 → 冻结语义和最终结构 → 接通全部调用者与失败路径 → 组合验证。

每项触发后从本表转成对应唯一专题或在本文件展开，不同时保留两份行动清单。完成项删除并将持久契约写入 notes；清单全部结束后归档本计划。不存在用兼容分支、后台无限任务或隐藏策略模拟这些扩展的许可。
