# 文件扩展操作与一致性能力

状态：按真实消费者触发的未来计划。基本文件、OAL 和服务目录的当前目标由[重构计划](todo-2026-10-07-fal-service-redesign.md)拥有，本篇只登记其明确范围外的扩展。旧基本 FAL 的交付事实见[历史档案](archived/todo-2026-09-fal-service-capabilities.md)，不能把其中的 Record/Handle/Take 模型带回新设计。

## 当前边界

本轮重构承诺真实受限目录授权、同文件 backing 的原子 Rename、完整 Property 读写、非快照单工流、Property/Stream Copy、直接成员/节点 Watch 及明确的完成和清理。跨原子域 Rename 返回 CrossFilesystem，Copy 保留已创建结果并区分未知完成；这些行为由主计划完整定义，不等待下列扩展才成立。

fs Property 与 OAL tag 均不含 capability。能力取得、复制或一次性交付由实际领域协议拥有，不再把“通用 Capability 属性 Copy”列作文件协议的延期方向。正式装配/监督、设备资源和业务授权分别从其所属计划推进。

## 条件触发的能力

| 能力 | 目标 owner 与范围 | 触发与完成标准 |
|---|---|---|
| 跨文件系统高层 Move | libfs 客户端组合或真实文件工具；原子 Rename 之外的复制后删除合同 | 出现文件管理、安装或迁移消费者；先明确并发源修改/名字替换、源删除授权、目录及属性范围、部分完成、未知结果与恢复，再验证两端失败/退出不会误删替代者。不能直接 Copy 成功后按原名字 Remove |
| 递归目录 Copy / Remove、额外元数据复制 | libfs 的显式有界任务；树遍历、一致性、取消、部分树和属性规则 | 出现备份、安装或目录树管理消费者；确定符号链接/边界/循环和源变化政策，验证跨 provider 大树及部分失败，不以用户栈递归冒充有界任务 |
| 内容快照、临时文件/原子内容发布、持久完成 | libfs 接口及实际存储 provider；与已有原子名字 Rename 区分 | 真实存储或稳定映像/持久配置需求；先闭合 snapshot、提交/崩溃/取消、资源来源和恢复，再验证旧读者、替换冲突和持久失败。当前内存 Sync=Unsupported 不冒充支持 |
| 后端复制加速 | 文件领域的显式优化接口及可回退客户端 | 有数据搬运成本证据，后端支持 reflink/服务端复制等；保持部分进度、授权、取消、释放及未知结果合同，不把加速等同于原子 Move |
| 递归/跨 provider Watch、可重放事件 | libfs 与实际索引/同步消费者；事件身份、日志、恢复和跨入口订阅图 | 出现索引、同步或审计需求；验证溢出重同步、服务重启、取消整张订阅图和历史保留，不能只扩 Notification 位数 |
| append 与额外打开政策 | libfs 与具体 backing；原子追加位置及显式创建/截断组合 | 真实日志或文件工具需求；并发写、名字替换、冲突、未知结果和部分完成有独立合同。现有 Open/CreateOpen 按主计划，不因此缺少完成语义 |

## 接手与归档

需求触发后，在本篇展开该能力或建立唯一专题并将该行改为入口，不保留两份独立行动清单。当前重构不为这些能力建设兼容 adapter、假消费者或隐藏后台事务；现有协议可直接完成当前承诺。

完成的扩展回填实际实现说明；所有条目结束后本篇归档。主计划只链接本篇的延期归属，不重复维护触发条件和验证进度。
