[2026-10-28 外围设备快照](ref-2026-10-28-virt-peripherals-user.md)保留当时的详细驱动分析，其中验收部署、静态基座尚未实施等描述不再代表本基线。本文扩展到整个用户态使用环境，按当前代码核定正式装配；不批量改写旧快照和其中的历史链接。

全项目仍处于[矫正区](../KNOWN_ISSUES.md)登记范围。这里记录实现事实，不把现有结构当成未来必须保留的设计依据，也不依据尚未审定的 ideas 宣称能力存在。

状态含义：

- **已有、范围有限**：存在实际机制或消费者，但不能外推到未支持的设备、授权或失败保证。
- **基础已有、待接入**：底层机制存在，尚未形成所需应用契约或正式消费者。
- **缺失**：当前源码组件及正式部署未形成这项能力，不表示 QEMU 或硬件本身不支持。

下表的补齐范围是需求边界，触发栏是选择任务时的参考，不构成已确认设计、硬性依赖或施工承诺。新方向未指定的进程名、库拆分和协议均留待所属任务确定。

| 领域 | 已有能力 | 使用边界与事实入口 |
|---|---|---|

| 发现与服务 | OAL/Namespace、文件与服务各自协议、服务注册/取得/撤出 | 目录可见、业务 Ready、进程存活分别是不同事实；[fs](../notes/impls/fs.md)、[service](../notes/impls/service.md) |

| 设备与资源 | 登记、授权、绑定/供应、Watch、驱动选择与按需出生、功能出口；MMIO/IRQ/DMA | 当前平台与 DMA 信任边界受限；[device](../notes/impls/device.md) |
| 文件机制 | 内存 backing、目录/属性/字节数据、Rename、Watch、流与客户端 Copy | 没有磁盘持久性；Copy 库存在不等于正式应用已经采用；[fs](../notes/impls/fs.md) |
| 时间 | 单调时间、绝对期限和等待 | 不是 RTC/墙上时间服务；[time](../notes/impls/time.md) |

当前[正式组态](../user/formations/system.toml)为 `finish=stay`，装配 `srv_device`、`srv_driver` 和承载文件/registry 的 `srv_fs`，并交付 PCI、xHCI、HID 按需驱动映像。没有正式交互应用、命令解释器或通用服务管理器。客体专用测试进程/组态已移除；磁盘上残留的 target 或未跟踪目录不能作为正式组件证据。

initfs 的 `formation` 和 `image/<组件>` 是 init 的装配输入，不是已经面向应用提供的 bootfs。文件/registry 的导出也不能代替真实应用的 Namespace 和授权接线。

## 扩展路线与建议顺序

以下是本次盘点建议，不变更 COMPASS 既有排期，不形成已确认目标设计。用户只确认将盘点写为 ref，尚未选择控制台路线、普通应用故障政策、存储介质或网络方案。

### 先形成首个交互环境

先设计并接通“输入输出设备 → 控制台会话 → 普通应用启动/退出 → 命令解释器与少量文件工具”。两条可选路线：

- **串口路线**：用户态串口及平台授权 → 双向字符会话 → 终端/命令与应用 I/O。不依赖显示栈或 USB 文字输入，但串口驱动和授权并未现成提供。
- **USB 键盘＋显示路线**：复用受限 HID 基础，补符合应用交付保证的输入/文字层；另建设显示输出和文本呈现，再接终端与应用。现有键盘链不能补足缺失的显示能力。

应用可直接组合已有 loader、文件、通信和执行设施；完整服务管理器、std、磁盘或图形合成不是所有交互路线的统一前置。是否先做进程委托服务，由选定应用的权限和生命周期确定。正式输出不能用封装 debug syscall 代替。

### 再按使用目标分支

| 使用目标 | 自然接续 | 不应混淆的边界 |
|---|---|---|
| 文件工具与启动资源 | 应用 Namespace/受限目录 → 只读启动来源或内存可写区 → 实际工具 | 应用 bootfs 不必依赖磁盘；库存在不等于消费者已接通 |
| 持久数据与长期部署 | 块设备 → 持久 provider/恢复 → 配置/仓库 → flush/停止 | 介质写成功不是全部持久保证；持久化接点必须在开放使用前闭合 |
| 网络或远程使用 | 网卡/数据面 → 协议栈与配置 → 实际网络应用；安全访问再接认证/熵源 | 网卡可枚举或收发一帧不是联网能力交付 |
| 本地图形使用 | 显示 → 文本终端或所需图形接口 → 输入归属 → 合成/窗口等实际需求 | 不要求先实现所有图形层才验证一个有限显示目标 |
| 更广设备/真实硬件 | 选定设备和平台 → 资源/总线协议扩展 → 功能应用 → 故障/兼容/性能证据 | 不从 QEMU 成功外推型号兼容、非一致 DMA 或恶意设备隔离 |
