# 内核疑难问题调查手册（debug playbook）

非确定性损坏/挂起类问题的调查方法论。源自 sifive_u 野跳转归因
（2026-08 ~ 09，三天，最终根因为 `free_subtree` 巨型栈帧越界）；
工具级坑位见 `plans/TOOLING-PITFALLS.md`，本篇只记方法。

## 流程
### 0. 先钉住现象存在于哪个代码版本

开发中间态的观察不等于已提交代码的缺陷。开工前先做两件事：

- **日志时间戳对提交时间**：现场产物的 mtime 落在哪两次提交之间？落在
  提交前的，它只能证明那份中间态代码有问题，不能归因到 HEAD；
- **先在目标版本上多轮复现**（多档位、多平台）。零样本就不是「很难
  复现」而是「可能不存在」——此时正确动作是重审原始证据的归属，而不是
  继续归因内核。

同样先排除**验证基础设施自身**：超时砍断、负载自身缺陷（如在 U-mode
执行特权指令）会伪造出与挂死逐字同形的现象（无 panic、无终态、日志
断在中段）。先看 recipe/脚本的收束条件与负载的终因允许集，再担心内核
（案例：`plans/archived/review-2026-08-29-thread-model-batch1.md` §A4/§B）。

### 1. 确定性复现优先

可复现是压倒一切的前提。QEMU `-icount shift=0` 固定客户机指令时序，
能把概率性崩溃变成逐字节相同的确定性轨迹；复现配方确定后，每轮
serial/DIAG 流先比对一致性再交叉引用证据——不同构建的布局不同，
跨轮引用地址是无效证据。

### 2. 定位一阶事件，不追下游症状

损坏类问题的表现面会轮换（野跳转/堆损坏/页表被抹/结构体全零），
全是同一第一笔坏写的下游。定位手段按代价递增：

- **checksum 探针**：对关键静态区（根表/HartLocal/注册表）周期算
  FNV 入环，仅变更记录——廉价，先排除大块嫌疑；
- **PA 监视**：TCG 插件记录目标物理区间的全部写入（PC/值/宽度），
  用于抓「谁写了这里」；
- **pmemsave 事后快照**：fatal 后全 hart 停放、内存稳定，monitor
  `pmemsave` 物理地址直读，绕开 gdb 批量模式与串口乱流两坑；
- **执行环窗**（execring + 快速停机）：夹住案发前最后 N 条指令。

判定写入语义必须看 PC 家族：memset 系与 memcpy 系的 PC 不同，
「主动清零」和「拷贝了零」是两条路径。

### 3. A/B 收窄嫌疑面

每次只改一个变量，用「让崩溃消失或必现」做判据：

- **泄漏实验**：故意不归还某类资源，崩溃消失 ⇒ 元凶在归还链内；
  反之亦然。这是把「时序窗口」翻译成「资源路径」的最快手段；
- **探针二分**：在候选路径插入几条真实指令的延迟，抑制 = 路径相关；
  注意空操作探针必须同步做对照，排除观察者效应误判；
- **worktree 对照**：独立 worktree 各持一个变量版本，同配方对跑。

### 4. 时序敏感 ≠ 时序问题

本案最大教训。「改栈大小就消失」「加延迟就抑制」「1/3 轮次失败」
全都指向竞态，但最终根因是**确定性的栈溢出**——溢出踩到哪、受害
hart 当时在干什么才是随机场。资源量敏感的现象，先做静态审计：

- 反汇编核对函数 prologue 的 sp 减量（`addi sp,sp,-N` +
  `sub sp,sp,N` 合计），对照栈预算；debug 构建帧远大于 release，
  `[T; 512]` 这类按值拷贝是大帧头号来源；
- Rust 没有 `-Wframe-larger-than` 等价物，构建期审计靠 objdump
  （`os/tools/audit_elf.py`，帧上限不大于链接脚本 `STACK_GUARD`，
  构建期从 ELF 符号表强制），见 `notes/impls/mm.md`「栈窗口」。

静态尺寸审计成本分钟级，应排在任何动态取证之前。

### 5. 归因后闭环

修复验证三件事缺一不可：

1. **反汇编确认机制消除**（本案：帧 0x40d0 → 160 字节、memcpy 消失）；
2. **同配方 A/B 压测统计**（本案：基线 6/6 未达静默 vs 修复后 15/15 全静默）；
3. **解释全部历史证据**——能统一解释所有旧签名（多样损坏面、回归
   提交、平台差异）的根因才可信；解释不了的旧证据要重审而不是忽略。

## 判读纪律

- 探针改动代码 ⇒ 布局移位，一切符号地址当轮 `nm` 重取；
- TCG 插件 `vcpu_index` 与 hartid 映射不可靠，per-vcpu 归因仅作参考；
- 插件回读内存取「写入值」不可靠（`qemu_plugin_read_memory_vaddr`
  不保证写已可见），需要精确值用 `qemu_plugin_mem_get_value`；
- 大日志用 rg 预过滤 + tail 采样，禁止逐行正则流扫；
- 无缓冲串口多 hart 输出交叠，grep 特征要宽松、关键结论交叉验证。
