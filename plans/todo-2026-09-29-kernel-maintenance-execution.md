## 目标与边界

目标：Close、终止、已提交映射修改及其回滚/退休不依赖调用者继续 syscall；每次不可抢占推进有结构上界，连续维护不饿死用户线程、期限和远端确认。相同承载可用于经过准入的批量分配准备，不能为分配和释放各造一套执行系统。

非目标：业务任务 executor、用户回调、文件系统政策、任意 kernel thread 框架。保留协作式执行是本轮推荐前提；若改为可抢占/可睡眠内核，必须另行闭合全套执行与锁语义，不能在本案顺手加入。

## 执行机制目标设计（设计轮次 1，已定稿）

经 advisor 审查一次、与 DeepAsh 两轮对抗收敛确定。标“用户确认”为用户明确决定，其余为收敛结论。前期候选与旧记录已移入历史快照。

### 工作记录

- **粒度**：每份独立责任一条记录，不是每对象一条。同一对象的独立责任（例如设备 CPU 映射撤销与 DMA 撤销）各有记录；动态操作在被接受时预付记录。
- **嵌入与准入**：记录嵌在负担它的拥有体内，侵入式挂队零分配；准入点即拥有体/操作的创建或接受，不存在独立“工作槽预算”。因此 LastCapability 与 Close 发布不可能返回 OOM/Busy；级联只挂子记录，内核栈深为常数。
- **保活**：Queued/Running/Blocked 期间队列持拥有体强根；从来源摘出、正在调用 wake 的 token 也持强根或有明确 quiescence。Done 后在锁外交还强根。
- **Done 即终结（用户确认）**：记录 Done 后不再承载新责任，新责任用新记录；迟到 wake 遇 Done 一律忽略。与 capability 侧“归零即终结、不复活”一致。
- **重复活动记录（等待源轮次 5 定稿）**：扫描来源的记录在一次活动无工作后返回 Idle，仍使用出生承载。activate(Idle) 接管本轮强根并入队，activate(Queued) 合并，activate(Running) 只置 notified。finish(Idle) 遇 notified 回 Queued，否则转 Idle 并带走本轮强根，锁外只 drop 此 Arc，不触及可能已经重新激活的新一轮。Done 仍永久拒绝激活，进入 Done 前由 owner 关闭产生新扫描责任的入口；不增加 Quiescent 状态。来源节点和线程清理契约由[等待分案轮次 5](archived/todo-2026-10-02-wait-source.md#设计轮次-5轮次-4-定向修正用户裁决禁止嵌套-waitset)拥有。

### 状态与唤醒

同一队列锁拥有状态、链接与执行租约，不设独立原子态。状态：`Idle → Queued → Running{notified} → Idle | Queued | Blocked | Done`。

| 事件 | 状态 | 结果 |
|---|---|---|
| wake | Blocked | 转 Queued 并挂接 |
| wake | Running | 只置 notified，不入队 |
| wake | Queued / Done | 无动作 |
| pick | Queued | 转 Running{notified=false} |
| finish(Ready) | Running | 转 Queued 挂队尾 |
| finish(Blocked) | Running | notified 则 Queued，否则 Blocked |
| finish(Idle) | Running | notified 则 Queued，否则 Idle，锁外交还本轮强根 |
| finish(Done) | Running | Done，锁外清理登记并交还强根 |

- Running 期间绝不直接改 Queued，防止两 hart 同时推进同一记录。notified 只在出队时清零。
- 依赖源自持锁完成登记+复检。SignalSource内部DONE/internal_done与wake状态捕获在同一来源临界区，允许OBJECT_WAIT→MAINTENANCE_QUEUE；该短边只改队列状态，Work.record为纯字段投影，不执行step/业务回调。publish合并/wake活跃记录的多余Arc在QUEUE门内借稳定执行根保证非last；Idle/Done返回潜在退休根，由调用者带出全部领域锁后drop，kick也在门外。其他来源按各自稳定根与回执合同锁外wake，不把此例外泛化为任意回调或最后析构。
- token 携带等待代次，迟到通知不作用于新等待周期或 Done 记录。
- 三个窗口：登记前完成由复检覆盖；登记后、提交 Blocked 前完成由 notified 覆盖；Blocked 后完成由重新入队覆盖。

### 队列位置与账户公平

- 全局两级队列：活跃账户环 + 每账户 Ready 记录队列，按资金账户 DRR；任意 hart 可领取。不选每 hart 队列 + 窃取：反例为 A 在 8 hart 均有工作、B 仅 1 hart，本地公平下 A 约得 15 倍 B，修正仍需全局记账。
- 摘取时预扣有界授予额度，返回后按实际占用结算差额；超出转为账户欠账下轮偿还。在途误差上界 = 在途数 × 单原子上界。
- 账户有 Running/Blocked 记录时账本保持存活，不因 Ready 暂空重置欠账。
- 选账户有界：每次仲裁只推进有界个账户，进度延续到下一安全点，不在锁内循环。
- 持锁内只做摘挂、预扣、状态转换；禁止 step、分配、析构级联、IPI 发送、依赖源查询与其他锁等待。IPI 解锁后发，队列非空是真值；idle 登记后复检。
- 性能：全局锁按批次争用（锁内常数时间 / 批次执行时间）。真实负载下持锁或等锁时间超过测量阈值时，改为每 hart 本地队列 + 全局账户虚拟时间；crate 的仲裁接口为纯值，不绑定锁结构，替换只改内核存储。

### 有限服务机会（用户确认的收口轮次）

- 结构性活性独立于计量精度。Account与per-hart U/M同一规则：每轮q费用单位、K=ceil(q/最小正表示单位)次服务机会；整数tick账本K=q。费用仍按真实采样归账，0仍为0，不虚扣tick或忙等。每个机会均有明确费用归属，选择失败/空维护仲裁亦覆盖；暂停/恢复计时不重新发机会。
- 每个机会至少产生一正单位费用时，费用会先于机会门耗尽，原费用加权轮转继续成立；机会先耗尽时丢本轮正的未用信用、保留负债，允许换出。该强制轮没有原CPU份额偏差界，只承诺有限机会结束。结构活性条件仍包括hart持续推进、有界原子/在途grant最终返回、紧急来源已有准入限制；持续外来债务注入不承诺该账户自有Work最低份额。
- Account领取grant消费机会，结束轮次必须等全部在途结清，迟到退款不进入新轮；新激活进next，当前批不被新准入无限扩长。U/M选Run和同轮Resume各领取一次，不因费用采样分段再计次；已领取机会允许完成当前段，耗尽只拒下一份。无另一类时借用空闲能力，正信用不跨轮积攒。
- Resume沿同一额度并重装timer，保留dispatch绝对线程期限；不能重复发线程时间片或类别量子。U原子涵盖选定类后的线程选择、准备、用户/syscall和退出；未选类共享仲裁、remote/timer紧急服务仍沿原排除边界。纯用户执行由既有timer截断。
- 本轮承诺结构性无饥饿和采样费用约束；物理CPU份额/数值时间界仍是具备执行计量合同的平台能力，不阻本链交付。详细类型、接线、验证与剩余完成门由[对象链审定轮次](archived/todo-2026-10-01-object-chain-kernel-integration.md#设计收口轮次有限服务机会与费用预算用户已审定施工中)承接；不建立尚无合格后端的meter facade。

### 队列锁（用户确认）

`os/kernel/src/sync.rs` 提供 ticket 原始锁（`next`/`serving` 两计数，FIFO），外层容器复用现有关本地中断与 rank ladder 断言；不做 crate。等锁上界：每 hart 至多一个待获取请求，最多排在 H−1 个短临界区之后。现有 `RawSpinlock`（CAS，无公平）不能给出该界；其余锁按需迁移（timer、remote 优先），全量退场另立锁替换记录承接。

### 结构上界与时间目标分离

- 三层契约：①到达本地检查点的最大间隔（本案以单步结构上界约束）；②从发布/到期到确认/通知的排队与服务延迟；③线程实际运行延迟。固定版本 SBI 与特权规范只要求有界、未给数值，故 timer 精度推不出②，TLB 协议推不出确认时限；`QUANTUM_NS` 不作依据。
- ②③的数值是系统政策参数，待定标；无平台 WCET 时只承诺结构性有限步与条件性时间界，QEMU 测量不称 WCET，不宣称硬实时。
- 成本：账本按平台定义的可归属采样费用结算，领域原语只提供结构上界（单原子最大规模、循环层数、锁链、潜在析构），共享原语由唯一实现拥有其上界。执行器不认识原语类型，无领域换算系数。每原子动作边界检查费用与机会预算，允许超出一个原子，超出入欠账。当前TIME只保证采样守恒，短段进展由上节有限服务机会保证；物理CPU份额须由独立执行计量合同提供，owner/触发/接通条件由[对象链唯一记录](archived/todo-2026-10-01-object-chain-kernel-integration.md#执行计量前置保留目标不以调度补丁替代缺失平台合同)拥有。
- timer/remote 为每 hart 定位短服务：每次摘有限项、提交仲裁与唤醒，不为每个 timer 建记录；仲裁引出的长清理交给已拥有该责任的记录。未处理完保持 pending，下一检查点继续；不得 arm 到已过期时刻造成中断风暴。

### 维护份额：每 hart 两类别有界时间轮转

- 每 hart 在 U（本 hart 兼容域可运行用户线程，内部保留域 FIFO）与 M（全局维护，内部账户 DRR）间轮转；不向域 FIFO 塞假线程。
- 有符号余额：采样执行费用全额扣减，轮到该类加q并重置K机会；余额>0且有机会才发下一执行，到检查边界完整扣账。负余额下界−δ，δ覆盖最后一次检查到停止之间的完整不可抢占尾段（含应归账锁等待、退场）。负债保留，不在独占区间清零；机会强制封轮/空闲都不积攒正信用。qM、qU均>0。
- 余额非正而跳过是仲裁推进，不是“无工作”：保留仲裁进度，不因此 WFI，不在 run 入口重置轮次；连续空仲裁照常服务 pending，开销计入开销边界。
- 条件性份额：计量代表实际占用且机会门未提前封轮时，双方持续有工作满足`S_M ≥ qM/(qM+qU)·A − E`，U对称；A扣除共享选类与紧急服务，E来自相位差、原子超出与计时误差。机会先耗尽的轮次不宣称此界，改由有限机会保证无饥饿。最大连续占用的数值仍需平台δ/计量条件；无用户线程hart可全借给M，不证明单线程期限或不可并行M工作的所有hart总保底。
- **紧急服务与份额（用户确认）**：U/M 份额只针对扣除紧急服务后的剩余 CPU；紧急服务容量由 timer、remote 各自 owner 用到达准入约束。
- **qM/qU（用户确认）**：不在计划冻结数值，当前政策由execution实现拥有；后续实测可以调整，不能以其数值宣称未具备平台合同的WCET/份额保证。
- 仲裁点：`run()` 处理完线程离场、pick 之前；连续 M 每批回到此点。`trap.rs` Completed→Resume 与 SSIP Resume 也须在统一返回边界结算当前类别，额度耗尽且另类可运行则转回 `run`。返回用户前 arm 线程量子、类别剩余额度、最近期限中最早者；trap/Resume 不重发额度。syscall 内核时间归 U，维护成本不归无关线程。

### 纯逻辑 crate 与内核分工

`os/maintenance` 拥有纯逻辑；内核提供实际存储、执行和硬件接点：

| crate（纯值、host 单测） | 内核 |
|---|---|
| 记录状态机 `transition(State, Event) -> (State, Action)`，含 notified 与等待代次 | 记录存储、侵入式链接、强根、ticket 锁 |
| 账户 DRR：选账户（有界推进）、预扣、结算、欠账 | 调用各类型 step、门铃 IPI |
| 两类别轮转器：有符号余额、选类、计费 | 接入 `sched::run/idle`、trap 返回边界、timer arm |

不接收回调、不反向依赖内核。Work返回Idle/Ready/Blocked/Done，Blocked前依赖已登记；费用由内核执行器统一采样，纯逻辑crate不提供领域伪造cost或调用Work。

### 内核拼装与当前接缝（原草图已接入）

**记录嵌入**

| 拥有体 | 记录 | 准入点 |
|---|---|---|
| 每个可终结对象（Receive 队列、MemoryObject backing、订阅集合等） | `retire: WorkRecord` | 对象创建成功即存在 |
| Process | 唯一回收记录，覆盖构造失败、终止与最终收束 | 进程创建 |
| 地址空间 | 整体退休记录（屏障达成后独占） | 地址空间创建 |
| 大分配准备对象 | 准备记录，取消切换到回滚阶段 | 操作被接受时（可拒绝） |
| 设备绑定（MMIO/IRQ/DMA） | 各自独立记录 | 绑定建立时 |

WorkRecord包含纯Record状态、侵入式链接及所属账户。拥有体实现对象安全的`Work::step(self: Arc<Self>) -> Outcome`，执行器原根保留到finish后的锁外处理，receiver clone直接支撑arm；无需自Weak或回填root锁。Queued/Blocked根由队列/Record持有，Running根在执行器局部；潜在最后析构在finish及全部领域锁外。费用由执行器统一采样，不由Work伪报cost。

**全局队列与账户**：一个 `MaintenanceQueue`（ticket 锁），内含活跃账户环；每个 Pool 资金账户带 `maintenance::Ledger` 与 Ready 记录链。账户只要有在途记录就挂在环上或由在途记录强持。每 hart 一个 `maintenance::Rotor`，hart 私有，无锁。

**锁序**：MAINTENANCE_QUEUE在业务/对象锁之后、HEAP之前，数字唯一真值在sync::ranks。持QUEUE不取其他锁、不分配、不执行潜在最后析构；发布可由业务门进入QUEUE，IPI一律在全部锁外。SignalSource内部完成允许前述来源→QUEUE短边，其余Hint/业务动作仍锁外；不能保留旧的“来源与QUEUE绝不嵌套”断言。

**事件执行点**

| 事件 | 位置 | 动作 |
|---|---|---|
| LastCapability | `CapTable` 锁外、调用 Close 的 syscall 返回前 | 对象 retire 记录 publish；Close 返回时责任已可达 |
| 表退出 | 进程回收记录的 step 内 | `shut` 后 `take_next_bounded`，摘出 cap 锁外 release，额度不足时剩余 cap 留在记录游标 |
| 级联 | 父 step 内 | 只 publish 子记录，不递归 step |
| 依赖完成 | SignalSource内部完成同来源门捕获wake；remote等沿自身锁外交接 | `wake(ticket)`返回潜在退休根；全部领域门外drop/kick |
| 选类与执行 | `sched::run` 离场处理后、pick 前 | `rotor.choose`；M 则锁内 visit→pick，锁外 step，锁内 finish+settle |
| 返回边界结算 | `trap.rs` Completed/SSIP Resume 前 | `rotor.charge(U, elapsed)`，额度耗尽且 M 可运行则转 Requeue |
| idle | `sched::idle` | 登记 idle 后复检全局队列非空；仅 Blocked 时可 WFI |
| timer/remote | 每批之间、run 循环顶 | 摘有限项；未完保持 pending，arm 到下一检查点 |

进程回收、VM 退休、capability 与维护的接缝已接通；当前实现从 [internals](../notes/impls/internals.md)、[task](../notes/impls/task.md) 和 [mm](../notes/impls/mm.md) 核实。

## PM 与设备管理的责任边界

PM 持有监督和终止政策，发起终止并观察资源收束；内核持有终止被接受之后的特权推进责任。把 PM 定为必须存活的可信回收执行者可以形成另一种一致的系统契约，但会让其存活成为回收活性前提；当前已选择自动回收，因此不再要求 PM 代跑 UnitOfWork。这里不删除用户态服务内部业务善后的责任。

设备侧消费者包括 MMIO 绑定的 CPU 映射撤销、IRQ 订阅/路由解绑与迟到事件收束、以及有平台保证的 DMA 映射撤销和同步。各自资源对象持有独立工作根，不能全部寄生于驱动 Process 回收：设备工作可能在进程退出后仍有未完成的硬件使用。

通用执行器不理解驱动名字、寄存器脚本、设备选择、业务排空或复位政策。已经提交的特权撤销由内核独立推进；用户态驱动/可信恢复 provider 提供其负责的硬件协议与完成事实，设备管理者协调不同资源与供应关系。具体硬件依赖按设备分案固定规范取证，本案不预设 IRQ、DMA 与 CPU 撤销的一套通用顺序。

驱动进程消失、CPU 映射撤销、硬件 DMA 已停止是不同事实。无可验证的停止/隔离证据时，相关 backing 继续由隔离责任保活，不退款、不复用。维护应停驻或报告明确的隔离结果，不能高优先级忙轮询，也不能用超时或已处理全部工作批次伪造安全完成。Close 的必成本地交接不等于故障硬件最终一定允许物理回收。

## 先减少总工作，再对剩余工作分步

1. **整拥有体释放**：保存真实拥有链和根，不在关闭时从全局表搜索“属于谁”。摘根可很短；子项的独立资源仍需逐项正确终结。
2. **释放不重新组装分配事务**：完整 mapping/对象关闭优先直接转交已持有的 ledger/backing/退休状态，不在关闭时重新拆大页、申请分片和资金。部分区间修改是另一个可拒绝操作。
3. **进程整体退休**：执行与已提交使用屏障达成后，使整个地址空间进入独占退休；不用针对每个区域重演 Running Unmap 的授权、竞争与同步协议。
4. **合并确认与退款批次**：可以合并同一地址空间/代次的失效，按真实 extent 释放物理库存；不能跨资金来源或共享 owner 伪合并。
5. **限制级联栈深**：最后引用触发新的收尾时移交工作，不递归释放任意深度对象图。

批量 free、页链归还、arena reset 可以减少管理工作，但不能抹掉共享引用、副作用通知和安全清零。延迟清零只是把成本移到再分配，必须在那里计入预算。

## 分配与回收的不同失败边界

| 操作 | 可失败时点 | 成为长工作时 |
|---|---|---|
| 普通新建/扩大资源 | authority 校验和准入阶段可以拒绝 | 内核持准备 owner 分批清零/建表；未成功发布前可取消并收束准备 |
| 合法 Close/已拥有资源完整释放 | 不因清理容量或临时繁忙拒绝 | 使用之前准入的状态，转交内核继续推进 |
| 部分修改/业务事务 | 在其明确提交点之前可拒绝 | 提交后由稳定 owner 完成，不返还伪造的可重试输入 |

大分配是单次请求的多步内部执行，还是由资源接口天然限制单次规模，必须由实际资源模型决定；不能用无依据的“小常量”把工作拆分责任推给所有用户。

## 验证

- 无 runnable 用户线程时，多批释放最终完成；其间 timer 唤醒的新线程获得调度。
- 多个拥有域持续产出工作时都有进度；单一巨大对象不会垄断执行。
- 依赖在登记前、登记中、刚停驻后完成均不丢唤醒；重复唤醒不重复执行 owner。
- 准入已经用满后合法释放仍可发布；队列承载不会向关闭方返回 OOM/Busy。
- 调用者与观察者全部消失后工作根仍在；零引用级联不增长到无界内核栈。
- 清零、PTE 操作、扫描与最后引用回调计入实际预算，不以一次函数调用冒充常数工作。

使用项目已有 host 和 QEMU 设施；实现闭合后按 BUILD-AND-TEST 执行规定检查及相关组合路线。实际接线与执行证据由对象链唯一记录拥有。

## 本链接入收敛结论（2026-10，LoneCrane 对抗）

- 账户即 Pool，欠账转移与公平范围见[预算分案账户形状](todo-2026-09-14-kernel-memory-budget.md#对象持有与释放链所需的账户形状收敛结论2026-10-与-lonecrane-对抗-8-轮advisor-一次)；debt transfer 为独立操作，不复用 `Ledger::settle`。
- **timer**：所有装填路径（含 `register_wait_timeout`）共用“已到期 → hart 本地 pending，未来 → arm”入口；pending 参与 run/Resume/idle 决策：有 pending 不 WFI，返回用户前装近期 timer 作后续检查；每次服务 qT 项，不 while 排空；expire 后续清理移交既有 Work。
- **remote**：完成事实按空间 + 事务代次唯一标记；先取 wake token 稳定根，再归还槽，锁外 wake；源登记 + 复检与 Running.notified 覆盖早到/迟到；最终析构只有界释放或 publish；零目标不造远端 ack。运输复用契约见[内存分案轮次 3](todo-2026-10-01-memory-redesign.md)。
- 上文施工前设计门已由crate、内核接入及审查修复关闭；当前政策参数来自execution实现，变化须测量触发。物理CPU份额/WCET依独立平台合同，锁争用优化见[性能专题](todo-2026-10-01-lock-performance.md)，均不回退为未完成的本链接线。

## 条件后续与完成边界

物理 CPU 份额、响应数值界及 WCET 必须由独立平台执行计量合同支撑；当前费用采样和有限服务机会不提供这一保证。需要对外承诺这些界限时，由执行/平台 owner 先核计量含义、归属、误差和不可抢占成本，再以真实平台证据验证，不能在调度器上虚扣 tick 或忙等补齐。

锁与队列布局只在实际争用/延迟证据触发后按[性能计划](todo-2026-10-01-lock-performance.md)优化；当前本链没有待接通消费者。门铃不可恢复失败遵守已选平台停止合同，静态保留不是 runnable 维护工作。
