# 外部规范与实现参照

本目录保存 eRhino 所依赖的外部契约，供设计、编码和 review 按固定版本取证。它不承载项目自己的设计决策；项目决策仍以 `notes/` 为准。

## 证据层级

1. `normative/` 中固定版本的正式规范；
2. `notes/` 中已经确认的项目设计；
3. 代码中可证明的不变量与测试；
4. `implementations/` 中固定版本的具体实现文档；
5. `pre-ai` 及其它历史代码，只作为缺陷考古和回归样本。

模型记忆不能单独支持外部契约结论。实现参照只用于确认现实中的指令/API用法、平台行为和已知硬件边界，不能作为 eRhino 架构选择的理由；设计必须从本项目需求独立推导，再用其它实现做反例检查。

## 使用方法

1. 从 `INDEX.md` 定位概念对应的规范文件。
2. 阅读完整小节及其引用的小节，不孤立摘取单句或表格行。
3. review finding 必须引用目录内路径和小节标题；规范没有明确约束时，结论标为待决策或待证明。
4. 当前语料不覆盖所需契约时，先从官方一手来源补齐并记录来源，再编写依赖该契约的代码。

目录中的上游正文保持原样；项目解释、采用范围和取舍写入 `notes/`，不直接修改上游副本。

## 版本与采用范围

固定版本是可复现的阅读基线，不等于项目自动采用该版本的全部能力。项目实际支持的 ISA 子集、最低 SBI 版本和必需扩展必须另行在 `notes/` 中成文。

## 更新流程

1. 从官方 release/tag 选择候选版本，阅读 changelog 并确认升级理由。
2. 核对许可证和上游 commit；以完整上游文件替换现有副本，不在副本上打项目补丁。
3. 更新 `MANIFEST.md` 和 `INDEX.md`。
4. 审查新旧规范差异对 `notes/`、代码和测试的影响。
5. 规范升级使用独立提交，避免与功能改动混合。
